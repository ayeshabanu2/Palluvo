### 1. [P3] Remove Duplicate Campaign Badge in Mobile Hero
**Affected File:** [`src/app/page.js:63–75`](src/app/page.js#L63-L75)

- **Reviewer Note:**
  - *“In the mobile-width preview, the image already carries an “Autumn / Festive 2026 Drape” pill, then the same campaign is repeated immediately below the image as “Autumn / Festive 2026 Collection” (src/app/page.js:55–70). The second badge adds redundant content and pushes the hero copy farther down. Please keep one campaign label at mobile sizes or make the two labels serve clearly different purposes.”*

- **Root Cause & Layout Geometry:**
  - On mobile screens (`< lg`), the hero showcases the campaign photograph in a dedicated visual grid card carrying an absolute pill badge (`Autumn / Festive 2026 Drape`).
  - Immediately underneath in the second grid row, the editorial text column was declaring another inline pill badge (`Autumn / Festive 2026 Collection`).
  - This created back-to-back duplicate campaign labeling on mobile touchscreens and unnecessarily displaced the primary `<h1>` headline, craft story, and primary CTA buttons downward.

- **Implementation Details:**
  - Updated the editorial text-column badge in `src/app/page.js:64` from `inline-flex` to `hidden lg:inline-flex`:
    ```jsx
    {/* Desktop-only Editorial Collection Pill (mobile already carries campaign badge in the image card) */}
    <div className="hidden lg:inline-flex items-center gap-2 px-4 py-1.5 rounded-full border border-[#D6B878]/40 bg-[#2B211D]/75 backdrop-blur-md mb-6 shadow-md max-w-full">
      <Sparkles className="w-3.5 h-3.5 text-[#D6B878] shrink-0" />
      <span className="text-[11px] uppercase tracking-[0.25em] text-[#D6B878] font-medium whitespace-nowrap">
        Autumn / Festive 2026 Collection
      </span>
    </div>
    ```
  - **Mobile screens (`< lg`):** Exactly one campaign label is rendered—the styled pill on the campaign image card. The text column begins directly with `<h1>Every drape, a little magic.</h1>`, significantly lifting headline, editorial copy, and "Shop Curated Collection" CTA into clear, immediate view.
  - **Desktop screens (`lg:` ≥ 1024px):** Where the mobile image card is hidden and the hero uses the full-bleed background layout, the editorial collection pill remains displayed above the headline as intended.

- **In-Browser Verification (Live Chrome CDP):**
  - **Mobile (390×844):** `visiblePillCount = 1` (`['Autumn / Festive 2026 Drape']`). `isTextColPillVisibleOnMobile = false`.
  - **Desktop (1280×800):** `visiblePillCount = 1` (`['Autumn / Festive 2026 Collection']`).

### 2. [P2] Make Mobile Navigation Drawer Accessible as an Overlay
**Affected File:** [`src/components/Header.js:70–125, 175, 290–325`](src/components/Header.js#L70-L125)

- **Reviewer Note:**
  - *“When #mobileMenuDrawer opens (src/components/Header.js:230), the accessibility tree exposes it only as a generic container and focus remains on “Open navigation menu”; pressing Escape also leaves the drawer open. Because this drawer covers the page, expose suitable modal/navigation semantics, move and contain focus within it, restore focus on close, and support Escape dismissal so keyboard and screen-reader users can operate it.”*

- **Implementation Details:**
  1. **Modal / Dialog & Navigation Semantics:**
     - Added `role="dialog"`, `aria-modal="true"`, and `aria-label="Navigation menu"` to `#mobileMenuDrawer`.
     - Wrapped inner links inside semantic `<nav aria-label="Mobile navigation links">`.
     - Updated `#mobileMenuToggle` button with dynamic state indicators: `aria-expanded={mobileMenuOpen}` and `aria-controls="mobileMenuDrawer"`.
     - Assigned `aria-hidden="true"` to the backdrop overlay element.
  2. **Automatic Focus Transfer on Open:**
     - Created `closeButtonRef` and `menuTriggerRef`.
     - Upon drawer mounting, focus automatically shifts to the Close button (`aria-label="Close menu"`), placing the screen reader and keyboard user immediately inside the overlay context.
  3. **Keyboard Focus Containment (Focus Trap):**
     - Attached a `keydown` listener querying all focusable elements inside `drawerRef.current`.
     - On forward `Tab`: when focus reaches the last focusable link (*My Orders & Profile*), pressing `Tab` wraps focus back to the *Close menu* button.
     - On reverse `Shift+Tab`: when focus is on the *Close menu* button, pressing `Shift+Tab` wraps backwards to the last focusable element. Focus is 100% contained within the drawer.
  4. **Escape Key Dismissal & Focus Restoration:**
     - Intercepts `Escape` keydown events globally while the drawer is open to invoke `setMobileMenuOpen(false)`.
     - On unmount / close, focus is automatically restored back to `#mobileMenuToggle` via `menuTriggerRef.current.focus()`.

- **In-Browser Verification (Live Chrome CDP):**
  - **Initial State:** `ariaExpanded = 'false'`, `ariaControls = 'mobileMenuDrawer'`, `ariaLabel = 'Open navigation menu'`.
  - **On Opening:**
    - `drawerExists = true`, `role = 'dialog'`, `ariaModal = 'true'`, `ariaLabel = 'Navigation menu'`.
    - `toggleAriaExpanded = 'true'`.
    - `navTag = 'NAV'`, `navAriaLabel = 'Mobile navigation links'`.
    - Focus shifted: `focusedElementTag = 'BUTTON'`, `focusedElementAriaLabel = 'Close menu'`, `isFocusOnCloseButton = true`.
  - **Focus Trap:** After sequential `Tab` key events, `isInsideDrawer = true` (all focus retained within dialog).
  - **Escape Dismissal:** Pressing `Escape` closes drawer (`isDrawerClosed = true`, `ariaExpanded = 'false'`).
  - **Focus Restoration:** `isFocusRestoredToToggle = true`, active element restored to `#mobileMenuToggle`.
