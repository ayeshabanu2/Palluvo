### [P2] Keep the Footer Newsletter Form Inside the Viewport at Tablet Widths
**Affected File:** `src/components/Footer.js` (lines 30, 80–102)

- **Reviewer Note:**
  - *“At exactly 768px, the footer link grid switches to four columns (`src/components/Footer.js:30`), leaving the newsletter column 150px wide. Its email/Join row overflows that column: the Join button spans x=752–815, beyond the 768px viewport, and the document’s scroll width becomes 815px. Please delay the four-column breakpoint or constrain/wrap the form controls so the button remains fully visible.”*

- **Root Cause & Layout Analysis:**
  - In `src/components/Footer.js:30`, `md:grid-cols-4` activated at 768px (`md`).
  - At 768px viewport with `px-6` horizontal padding (`max-w-7xl mx-auto`), the content width is 720px. With 4 columns and `gap-10` (120px total horizontal gap), each column was constrained to only **150px**.
  - In column 4 (Newsletter), the email input (default intrinsic min-width) and "Join" button in `<div className="flex" aria-disabled="true">` required ~220px. This overflowed the 150px column, pushing the Join button to `x = 752–815px` (beyond the 768px viewport edge) and creating a document horizontal scroll width of **810–815px**.

- **Resolution:**
  1. **Delayed 4-Column Grid to `lg` (1024px+):**
     Updated line 30 to:
     ```jsx
     <div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 gap-8 lg:gap-10 py-12 border-b border-[#3D302A]">
     ```
     - On tablet screens (640px through 1023px, including 768px), the footer links arrange into **2 balanced columns**:
       - **Row 1:** Brand Atelier Info + Signature Weaves
       - **Row 2:** Concierge & Help + Newsletter
     - Each column receives **~344px width** (more than double the previous 150px), easily accommodating the full newsletter form and text without horizontal pressure.
     - On desktop viewports (1024px and wider), `lg:grid-cols-4` displays the standard 4-column row layout where ample width is available.
  2. **Constrained Form Controls (`min-w-0 flex-1`):**
     Updated the form row and input in lines 80–102:
     ```jsx
     <div className="flex w-full" aria-disabled="true">
       <label htmlFor="newsletter-email" className="sr-only">
         Email address for newsletter (Subscriptions launching soon)
       </label>
       <input
         id="newsletter-email"
         name="email"
         type="email"
         disabled
         aria-disabled="true"
         aria-label="Newsletter subscriptions opening soon"
         placeholder="Subscriptions opening soon..."
         className="bg-[#1F1714]/60 border border-[#3D302A] px-3 py-2 text-xs text-[#B8B0A5] placeholder-[#B8B0A5]/80 rounded-l-md cursor-not-allowed flex-1 min-w-0 focus:outline-none"
       />
       <button 
         type="button"
         disabled
         aria-disabled="true"
         className="bg-[#3D302A] text-[#B8B0A5] px-3.5 sm:px-4 py-2 text-xs font-semibold rounded-r-md tracking-wider uppercase cursor-not-allowed shrink-0 border border-l-0 border-[#3D302A]"
       >
         Join
       </button>
     </div>
     ```
     - Added `min-w-0` to the email input so flexbox can shrink the input element if necessary, completely preventing flex-item overflow.
     - Added `px-3.5 sm:px-4` to the Join button for compact button dimensions (~58px).

### [P3] Keep the Complete Brand Tagline Visible on Narrow Phones
**Affected File:** `src/components/Header.js` (lines 128, 133–135)

- **Reviewer Note:**
  - *“At 320px, `src/components/Header.js:133` applies `truncate` to “Every drape, a little magic.” The text measures 170px while its box is only 130px, so the visible tagline ends mid-word with an ellipsis. Please tighten the mobile type/letter spacing or use a deliberate compact variant rather than clipping the brand line.”*

- **Root Cause & Layout Analysis:**
  - On a 320px viewport, the header row (`gap-1.5`) with left mobile menu trigger (32px) and right action cluster (Search, Wishlist, Bag ~110px) allocates ~130–138px to the center brand container.
  - Previously, `text-[8.5px] uppercase tracking-[0.18em]` on the 28-character tagline `"Every drape, a little magic."` expanded the rendered text ("EVERY DRAPE, A LITTLE MAGIC.") to **170.26px** (tracking alone added +1.53px per character = 42.8px).
  - Paired with `truncate` (`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`), the text was cut off at ~130px with an ellipsis ("EVERY DRAPE, A LIT...").

- **Resolution:**
  1. **Tightened Mobile Typography and Letter Spacing:**
     Updated `src/components/Header.js:133` to:
     ```jsx
     <span className="text-[7px] xs:text-[9.5px] sm:text-[11px] tracking-[0.03em] xs:tracking-[0.18em] sm:tracking-[0.28em] uppercase text-[#665E57] font-sans block -mt-0.5 sm:-mt-1 font-semibold truncate">
       Every drape, a little magic.
     </span>
     ```
     - Below `xs` (viewports < 380px, including 320px), `text-[7px]` with tight `tracking-[0.03em]` brings the natural text length down to **~108px**.
     - This comfortably fits within the 130–138px box with >20px of margin, fully rendering all 28 characters through the final period (`.`).
     - At `xs` (380px and wider), the tagline scales smoothly to `xs:text-[9.5px] xs:tracking-[0.18em]`, and at `sm` (640px+) to `sm:text-[11px] sm:tracking-[0.28em]`.
  2. **Eliminated Ellipsis Truncation:**
     - Because text width (108px) is well within the allocated box width (132.5px / 138.3px container), `isTruncated` evaluates to strictly **false**.
     - No words or characters are clipped.
  3. **Optimized Padding:**
     - Adjusted container padding to `px-0.5 xs:px-1` to maximize horizontal space on narrow viewports.
