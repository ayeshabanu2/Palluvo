### 1. [P2] Implement the Search Overlay as an Accessible Dialog
**Affected File:** [`src/components/Header.js:70–75, 128–184, 292–302, 427–475`](src/components/Header.js#L128-L184)

- **Reviewer Note:**
  - *“src/components/Header.js:360 renders the overlay as plain containers without dialog semantics or modal state. In the live preview, pressing Escape leaves it open, and tabbing from the search field moves focus to the underlying “SHOP CURATED COLLECTION” link. Please expose it as a modal dialog, contain focus while open, support Escape dismissal, and restore focus to the trigger when it closes.”*

- **Root Cause & Modal Semantics:**
  - Previously, `showSearchModal` rendered a generic `<div>` overlay without ARIA dialog attributes, modal state flags, or keyboard listeners.
  - Tabbing from the input bypassed the dialog container into background elements (such as hero anchor links), Escape did nothing, and closing the overlay dropped focus to `document.body` rather than returning to the search trigger button.

- **Implementation Details:**
  1. **Modal Dialog Semantics & Trigger State:**
     - Exposed the search overlay as a modal dialog on `#searchModal` with `role="dialog"`, `aria-modal="true"`, and `aria-labelledby="searchModalTitle"`.
     - Assigned `id="searchModalTitle"` to the dialog heading (*"Discover Signature Sarees"*).
     - Backdrop overlay carries `aria-hidden="true"`.
     - Added `ref={searchTriggerRef}`, `id="searchModalToggle"`, `aria-expanded={showSearchModal}`, and `aria-controls="searchModal"` to the mobile search trigger button.
  2. **Automatic Focus Transfer on Open:**
     - Created `searchInputRef` and `searchCloseBtnRef`.
     - Upon opening `showSearchModal`, focus is automatically moved directly into `#overlaySearchInput`, allowing users to start typing immediately without extra navigation steps.
  3. **Keyboard Focus Containment (Focus Trap):**
     - Attached a `keydown` listener monitoring `Tab` / `Shift+Tab` cycles strictly inside `searchDialogRef.current`.
     - Forward `Tab` cycles: `overlaySearchInput` → Submit Button (*"Search Catalog"*) → Close Button (*"Close search"*) → loops back to `overlaySearchInput`. Focus never leaks to underlying background links.
     - Reverse `Shift+Tab` cycles backwards from `overlaySearchInput` to the Close Button.
  4. **Escape Key Dismissal & Focus Restoration:**
     - Pressing `Escape` intercepts the event, calls `setShowSearchModal(false)`, and cleans up event listeners.
     - Upon dialog dismissal/unmounting, focus is automatically restored back to `#searchModalToggle` via `searchTriggerRef.current.focus()`.

- **In-Browser Verification (Live Chrome CDP):**
  - **Initial Trigger State:** `ariaExpanded = 'false'`, `ariaControls = 'searchModal'`.
  - **On Opening:**
    - `modalFound = true`, `role = 'dialog'`, `ariaModal = 'true'`, `ariaLabelledby = 'searchModalTitle'`.
    - `triggerAriaExpanded = 'true'`.
    - Initial focused element: `focusedElementId = 'overlaySearchInput'`, `isFocusOnSearchInput = true`.
  - **Focus Trap:**
    - Tab 1 → Submit Button (*"Search Catalog"*).
    - Tab 2 → Close Button (*"Close search"*).
    - Tab 3 → Wraps around back to `overlaySearchInput` (`isWrappedToSearchInput = true`).
    - Focus containment check: `isFocusInsideModal = true` (0 background leak).
  - **Escape Dismissal & Focus Restoration:**
    - Pressing `Escape` closes modal (`isModalClosed = true`, `triggerAriaExpanded = 'false'`).
    - Focus restored: `isFocusRestoredToTrigger = true`, `activeElementId = 'searchModalToggle'`.

### 2. [P2] Give Both Search Fields a Programmatic Accessible Name
**Affected File:** [`src/components/Header.js:258–275, 450–470`](src/components/Header.js#L258-L275)

- **Reviewer Note:**
  - *“The desktop field (src/components/Header.js:203) and overlay field (src/components/Header.js:374) rely on placeholder text without an associated <label> or aria-label; the live accessibility tree reports the overlay control only as an unnamed text field. Please add explicit labels so screen-reader users can identify each field even after they start typing.”*

- **Root Cause & Accessibility Tree Exposure:**
  - Both `<input type="text">` elements relied exclusively on `placeholder` attributes.
  - When users enter query text or assistive technology inspects the accessibility tree, placeholder text no longer serves as an accessible name, leaving the inputs reported as unnamed text fields.

- **Implementation Details:**
  1. **Desktop Search Field (`src/components/Header.js:258–275`):**
     - Enclosing form tagged with semantic `role="search"`.
     - Associated an explicit visually hidden label:
       ```jsx
       <label htmlFor="desktopSearchInput" className="sr-only">
         Search sarees catalog
       </label>
       ```
     - Added programmatic attributes to input: `id="desktopSearchInput"` and `aria-label="Search sarees catalog"`.
  2. **Overlay Search Field (`src/components/Header.js:450–470`):**
     - Enclosing form tagged with semantic `role="search"`.
     - Associated an explicit visually hidden label:
       ```jsx
       <label htmlFor="overlaySearchInput" className="sr-only">
         Search signature sarees
       </label>
       ```
     - Added programmatic attributes to input: `id="overlaySearchInput"` and `aria-label="Search by silk type, color, region, or weave"`.
     - Decorative search icon explicitly marked `aria-hidden="true"`.

- **In-Browser Verification (Live Chrome CDP):**
  - **Desktop Search Field:**
    - `id: 'desktopSearchInput'`
    - `ariaLabel: 'Search sarees catalog'`
    - `hasAssociatedLabel: true` (`labelText: 'Search sarees catalog'`)
    - `formRole: 'search'`
  - **Overlay Search Field:**
    - `id: 'overlaySearchInput'`
    - `ariaLabel: 'Search by silk type, color, region, or weave'`
    - `hasAssociatedLabel: true` (`labelText: 'Search signature sarees'`)
    - `formRole: 'search'`
